# TestScene 音声認識の比較検証

## 切り替え方

TestScene の Hierarchy で `TestSceneVoiceManager` オブジェクトを選び、同名コンポーネントの **Input Settings → Input Mode** を変更する。Play 中も切り替え可能。既存シーンの既定値は `PushToTalk` のまま。

| Input Mode | 動作 |
| --- | --- |
| Push To Talk | 従来どおり左トリガーを押して発話し、離して確定。1回の押下で1コマンド。押下中にVoskが確定した場合も従来どおり実行する。 |
| Continuous Final Only | ボタン操作なしで音声を渡し続け、Voskの発話確定ごとに1コマンド実行。確定待ちによる遅延を比較する基準。 |
| Continuous Early Command | ボタン操作なし。途中結果が登録キーワードと全文一致し、候補が安定したら早期実行。早期実行できなかった発話は従来の確定結果判定に進む。 |

モード切替時は認識途中の音声・候補・待機中の結果を破棄する。切替後に改めて話す。Play 中に変更した Inspector の値は、通常どおり Play 終了で戻る。Quest ビルドの初期モードを変えるには、編集モードで変更してシーンを保存してからビルドする。

検証モードは `Time.timeScale == 0` またはアプリ非アクティブ中に受付・実行を停止する。復帰時も途中結果を破棄する。これは音声処理への投入停止であり、マイク自体の録音停止ではない。PTTの既存の受付条件は維持している。

## 調整項目

**Continuous Recognition Experiment** に以下を追加した。

- **Early Command Stable Duration**：初期値 `0.15秒`。登録語と一致した候補を初めて受け取った音声チャンクから、同じ候補が継続する必要がある時間。`0` は最初の一致で実行。これは「発話が終わってから0.15秒で反応する」という保証ではない。音声を投入した時刻を基準にするため、処理結果が一度に到着しても安定時間をフレーム時間で誤判定しない。
- **Show Experiment Timing Log**：検証ログのON/OFF。Consoleの検索欄で `[VoiceExperiment]` に絞り込める。PTTでも比較用ログを出せる。

早期実行には文字の正規化後の全文一致を使用し、曖昧一致・部分文字列一致は使用しない。発話途中の候補が空になる、別候補になる、未登録語になると安定時間をやり直す。確定結果には既存の完全一致／曖昧一致の判定を維持している。登録キーワードと異なる言い回しは、確定まで待つ場合がある。

早期実行後はVoskの発話確定まで再実行を抑止する。最終結果が空でも、その確定を受け取れば次の発話を受け付ける。同じコマンドも次の発話として再実行できる。**間を空けずに複数コマンドを連結すると、1発話として最初の1コマンドだけ実行される場合がある。** この実装は発話確定待ちを短縮するVADや、複数コマンドの文分割を追加するものではない。

ポイント判定、ハート消費、表情・体・目線のリアクション、HUD更新は既存の実行経路を使用する。早期実行がポイント不足で失敗しても、同じ発話の最終結果で再試行・再判定しない。

## ログの読み方

| ログ／値 | 意味 |
| --- | --- |
| `mode=... suspended=...` | モード切替または受付停止／復帰。 |
| `candidate=...` | 早期実行できる登録語候補の検出。 |
| `accepted ... source=partial/final` | コマンドとして採用した時刻。`partial` は早期実行。 |
| `submit-to-accept` | 判定に使った最後の音声チャンクを投入してから、メインスレッドがコマンドを採用するまで。発話全体の所要時間ではない。 |
| `final ... submit-to-result` | 最後の音声チャンク（PTTの終了時は確定要求）を投入してからワーカーが結果を作成するまで。キュー待ち時間を含む。 |
| `result-to-main` | ワーカーが結果を作成してからメインスレッドで受け取るまで。 |
| `early-to-final` | 早期採用から、その発話の確定結果受信まで。同じ発話で確定待ちをどれだけ先行できたかの参考値。 |
| `reaction=requested ... accept-to-request` | 採用からリアクション開始処理を行うまで。Animatorの遷移・ブレンド後に画面で動きが見える時刻ではない。 |
| `reaction=point-rejected` | 認識済みだがポイント不足等でリアクション不成立。 |
| `reaction=no-target` | ポイント判定は通ったが実行対象のリアクションが開始されなかった。 |

`t` は全スレッド共通の単調増加時計による秒数で、録画時刻やUnityのゲーム内時刻とは一致しない。**発話の音響的な終了時刻、実際の画面上のアニメーション開始は自動測定していない。** 音声付きの実機録画で、語尾から動きが見え始めるまでの時間を別途確認する。

## 実機比較手順

1. 同じ距離・ペンライト条件・BGM音量を使い、ポイント判定を通せる状態にする。
2. 3モードそれぞれで同じコマンドを10回程度話す。まず各発話を十分に区切り、結果を比較する。
3. 発話の語尾から目に見える動きまでの時間、実行できた回数、二重実行数を記録する。早期モードでは `source=partial` の割合と `early-to-final` も確認する。
4. 同じコマンドの繰り返し、別コマンドの連続、短い発話間隔を試し、次の発話を取りこぼす境界を確認する。
5. プレイヤーが黙った状態でBGM・キャラクター音声を流し、未登録の会話も試して誤反応を記録する。無音検出だけで音源を区別できるわけではない。
6. ポイント不足時に `point-rejected` が出て二重判定されないこと、途中候補がある状態でのモード切替・ポーズ・復帰で古いコマンドが実行されないことを確認する。
7. 早期モードの安定時間を必要に応じて `0.1 / 0.15 / 0.25秒` で比較する。最後にPTTへ戻して従来の操作も確認する。

## 開発時の確認

Unity 6000.5.1f1 の生成済みコンパイラー設定を使い、Editor向け・Player向けのスクリプトコンパイル成功を確認した。古いPlayer向け設定には現行の `PenlightHeartFeature.cs`、`VoiceCommandHUD.cs` と `OECULogging.Runtime` 参照が含まれていなかったため、検証コマンドで補った。UnityからのAPKビルドを実行したものではない。

認識結果処理の実ソースを抽出し、Unity/Voskの外部境界をスタブに置き換えたハーネスで、安定候補、途中候補の無効化、二重実行防止、空の確定結果からの復帰、次コマンド、世代違い結果の無視、受付停止、PTTの1押下1コマンドを含む14項目を検証した。

これは実マイク・Voskモデル・Quest上の描画を通したテストではない。認識速度・誤反応率・実際の動き出しは上記の実機比較で評価する。
