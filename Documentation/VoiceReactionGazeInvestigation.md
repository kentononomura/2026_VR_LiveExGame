# 音声リアクションの向き調査（2026-09-12）

## 修正結果（同日）

ユーザーの修正依頼を受け、軸設定、追従方向、参照管理、追従強度の順に修正した。以下の「修正前の調査」は履歴として残す。

- 胸・首・頭の正面軸をローカル+Y、上方向を-Xへ統一。親の回転に依存する部分的な軸マスクを解除し、MultiAimの角度上限で補正を制限する。
- LookAt/UnityChanCallはRig Weight=1、Head Weight=1、Chest Weight=0.65。頭の最大補正85度、胸60度。胸には自然な姿勢が残り、頭は可動範囲内で目標を向く。
- HMD方向を前方へ切り詰める処理と固定2mターゲットを廃止。実際の方向・距離を平滑化して使用する。
- ルート基準で左右85度／上下45度までは通常追従。その外側25度で追従を減衰し、左右110度／上下70度以遠では収束後に追従しない。背後を向くためのルート旋回は追加していない。
- 目線と距離判定のプレイヤー参照を共通化。0.5秒ごとに参照を再確認し、参照喪失中は補正を無効化、再取得後は滑らかに再開する。
- `Show Gaze Diagnostics` をTestSceneVoiceManagerのInspectorに追加。通常は無効。Play中に有効にすると、リアクション中に `[VoiceGaze]` ログとして対象名、左右・上下角、追従Weight、Rig Weight、実際の頭とHMD方向の誤差を0.5秒ごとに出力する。

### 検証結果

Unity 6000.5.1f1の分離した検証プロジェクトで、実際のPrefab・Avatar・Animator Controller・追加FBX・ダンスFBXと、修正したソースのAim生成処理／ターゲット追従処理を使用した。

1. **軸の確認**：正面、左右45度、上下20度で頭の向きと上方向を検証。
2. **ターゲット追従**：ルート回転3種類 × HMD左右方向6種類 × 距離3種類の54ケースが成功。背後方向を別方向に置換しないこと、追従の減衰、参照喪失・再取得・基準点と同位置の場合を確認。
3. **ダンス＋リアクション**：Pointing/Heart × 再生位置10/50/90% × 正面・左右45/80度・上下20度の42ケースが成功。頭の方向誤差は最大0.03度。これは静止ターゲット・補正Weightが上がった状態の結果であり、実機の移動中やブレンド途中の誤差を保証する値ではない。
4. **Root Motion・足**：ダンスと各リアクションを120フレームずつ再生し、目線補正あり／なしでRoot Motionの差分と両足位置が一致することを確認。
5. **コンパイル**：元プロジェクトのUnity生成コンパイラ応答ファイルを使ってAssembly-CSharp全体を別出力へコンパイルし、終了コード0。`git diff --check`も成功。

実機VRのHMDトラッキング・音声入力・描画を含む通し確認は未実施。実機では正面、左右、HMD上下、プレイヤー移動中、背後から戻る場合の動きを診断ログと合わせて確認できる。

## 修正前の調査：結論

HMD位置からプレイヤー方向を求める実装は存在する。ただし、現在の胸・頭のAim設定はUnityちゃんのボーン軸と一致していない。また、目標方向の制限と低い追従Weightにより、正しい位置を取得できてもプレイヤー正面を向く保証はない。

前回の調査時点では、ゲーム側のコード・シーン・アニメーション設定を変更していなかった。

## 確認方法と範囲

- `TestSceneVoiceManager.cs`、`TestScene.unity`、`unitychan_hw.prefab`、`XROriginVR.prefab`、StageDirector、および同梱Animation RiggingのMultiAim実装を確認。
- Unity 6000.5.1f1の一時プロジェクトで、実際のUnityちゃんPrefabとAvatarを読み込み、ボーン軸を測定。
- 現在の `StabilizedAimTargetFollower` をコピーして実行し、仮想HMDの位置に対するAim方向を測定。
- 実行中のVRセッションのHMD参照・姿勢は直接取得していない。以下の実測はPrefab初期姿勢および分離した方向計算についての結果である。

## プレイヤー方向の取得

`SetupAnimationRigging` は `FindAnyObjectByType<XROrigin>()` の `Camera` を優先し、取得できなければ `Camera.main` を使用する。TestSceneの参照先XRリグにはMain Cameraが設定されている。StageDirectorはキャラクター生成に先立ってXRリグを用意するため、通常の生成順序ではカメラが先に存在する。

毎フレーム `HMD位置 - キャラクタールート上の基準点` から方向を計算している。カメラが向いている方角ではなく、プレイヤーがいる位置を使う点は適切。

ただし、次の制約がある。

- 参照取得はリグ構築時の一度だけ。取得失敗時や後からカメラを差し替えた場合の再取得はない。
- `playerTransformOverride` は距離判定用で、Aimのターゲット取得には使用されない。
- 実際に選ばれたカメラの名前・位置、プレイヤー方向と顔方向の誤差を記録する診断ログはない。このため、実際のVRセッションで正しいカメラを取得したかは現状の保存設定だけでは確定できない。

## ボーン軸の不一致（実測で確認）

Prefabのルート座標で測定。ルートの正面を+Z、上を+Yとする。

| ボーン | ローカルXの向き | ローカルYの向き | ローカルZの向き |
|---|---|---|---|
| Chest | (-0.001, -0.951, 0.310) | (0.015, 0.310, 0.950) | (-1.000, 0.006, 0.014) |
| Head | (-0.016, -0.991, 0.136) | (-0.042, 0.137, 0.990) | (-0.999, 0.010, -0.043) |

このAvatarにはUpperChestがなく、コードはChestへフォールバックしている。

- **胸**：コードは `aimAxis=Z`、`upAxis=Y`。実際はYがほぼ正面、Zがほぼ左方向であり、胸の横方向をターゲットへ向ける指定になっている。
- **胸の回転制限**：`constrainedYAxis=true` のみ。MultiAimは親のローカル空間で軸を制限する。胸の親Spine1のYはほぼ正面であり、ワールド上方向を中心とする水平旋回の指定になっていない。
- **頭**：`aimAxis=Y` は正面方向と整合するが、`upAxis=Z` は実際にはほぼ左方向。上方向の軸指定が不一致。また回転をX/Yのみに制限しているため、モデルの軸に合わせて上下追従の可否も見直す必要がある。

単純なWeight増加ではこの軸不一致は直らず、誤った回転を強める可能性がある。まずモデル基準の正面軸・上軸・許可回転軸を揃えて再測定する必要がある。

## プレイヤー方向そのものの制限（実測で確認）

シーンは `lookAtMode=Stabilized`。ルート正面基準で左右60度、上下25度に切り詰めた方向へ、基準点から2mの位置にAimTargetを置く。HMD位置そのものをAimTargetにしているわけではない。

| 実際のHMDの左右角度 | AimTargetの左右角度 | 方向の誤差 |
|---|---|---|
| 0度 | 0度 | 0度 |
| 45度 | 45度 | 0度 |
| 90度 | 60度 | 30度 |
| 135度 | 60度 | 75度 |
| 180度 | -60度 | 120度 |

180度付近は左右境界のため、わずかな位置変化で切り詰め先の符号が変わり得る。ダンスでルートが回転すると、同じプレイヤー位置でも制限内外が変わる。

キャラクタールートをプレイヤーへ回す処理は意図的に無効化されている。Inspectorに残る `characterFacingYawOffset` と `characterFacingSmoothTime` は未使用で、調整しても向きは変わらない。

## 補正の強度

コマンド別overrideはシーンで無効のため、コード内の値が使われる。

| 項目 | こっちみて（LookAt） | ユニティちゃん（UnityChanCall） |
|---|---|---|
| Rig Weight | 0.72 | 0.48 |
| 頭Constraint Weight | 0.55 | 0.55 |
| 頭の実効Weight（積） | 0.396 | 0.264 |
| 胸Constraint Weight | 0.22 | 0.18 |
| 胸の実効Weight（積） | 0.1584 | 0.0864 |
| 頭の補正角度上限 | 50度 | 50度 |
| 胸の補正角度上限 | 40度 | 40度 |

これらのWeightは角度そのものではないが、ターゲットに完全一致させずアニメーション姿勢を強く残す設定である。胸のInspector初期値0.12は、リアクション時にはコマンド別値へブレンドされる。

眼球は別の `VoiceEyeContactIK` で制御されるが、body/head Weightは0のため、上半身・顔の向きは直さない。眼球も制限済みAimTargetを使用する。

## 修正する場合の順序

1. 胸と頭のボーン軸・回転許可軸を実モデルに合わせ、正面・左右・上下のターゲットで向きと傾きを検証する。
2. 選択したHMD参照、実際の方向、制限後の方向、頭・胸の方向誤差を実行中に確認できる診断を追加する。
3. 軸が正しい状態でコマンド別Weightと角度上限を調整し、Pointing/Heartとダンスの合成中も測定する。
4. 横・後方のプレイヤーへ対応する範囲を決める。現在は上半身だけでRoot Motionを保護する設計なので、首胸の可動域を超える方向を向くにはルート旋回とダンス移動の扱いも検討が必要。

今回の調査は、新しいFBX自体が逆向きであると断定するものではない。既存の目線制御に軸の不一致と追従制限があることを確認した。
