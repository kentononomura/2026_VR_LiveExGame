# 大型スクリーンの音声認識コメント

VR_GameScene の `StageDirector` が生成する `Back Screen` プレハブに
`StageRecognitionComments` を追加。既存映像の前面へ透明な World Space Canvas を重ねる。
メッシュのローカル bounds に合わせて表示領域を作り、観客側の +Z に向ける。
スクリーンと同じレイヤー20を使用し、スクリーン撮影用カメラへの映り込みを防ぐ。

## 表示仕様

- Vosk の確定した `text` を、コマンド成功・失敗に関係なく1結果につき6つ複製して同時に表示開始。
- 途中結果は表示しない。途中結果でリアクション済みでも、後の確定結果は表示する。
- 白文字・黒い縁取り。文字サイズは従来の5倍（64→320）。画面外をマスクする。
- 例: 「かわいい」と認識したら、同じ「かわいい」が6つ同時に右端から流れ始める。
- 新しい認識結果を受信したら、前の表示を置き換え、新しい文字の6つを同時に開始する。
- 通過時間はコメントごとに独立して抽選する。右端から左端の外まで3〜7秒で等速移動する。
- 上下に文字の余白を確保した表示可能範囲を複製数（通常6）の帯に等分し、各帯に1つずつ配置する。帯の中央50%の範囲で高さをランダム化し、隣接する帯の境界付近への集中を防ぐ。
- 表示中の高さ・速度は固定。文字サイズと画面の高さによって文字の一部が重なることはあるが、開始位置の高さは上下に分散する。
- 待機キューは使用しない。6つはそれぞれ左端を通過した時点で消え、繰り返さない。
- 原文の空白と `[unk]` を保持する。改行は空白へ置換、前後の空白は除去。
- 空の結果・無音・不正JSONは表示しない。失敗理由の文言は追加しない。
- リッチテキストは無効。認識文字列にタグのような文字があってもそのまま表示。
- 無効化時に全コメントをリセット。Canvasと専用マテリアルは破棄時に解放。
- コメント移動は unscaledDeltaTime を使用する。

音声マネージャーの認識世代・受付停止の検査後、既存コマンド照合の前に通知する。
認識・コマンド判定・ポイント消費・リアクションの条件は変更しない。
空でない確定結果でも、認識器が別々の結果として返した発話はそれぞれ表示する。

## 調整

`Back Screen.prefab` の `StageRecognitionComments` で調整する。

| 設定 | 初期値 | 内容 |
| --- | --- | --- |
| Minimum / Maximum Travel Seconds | 3 / 7 | コメントが画面を通過する秒数のランダム範囲 |
| Font Size | 320 | 横1920を基準にした文字サイズ。従来の5倍 |
| Copies Per Recognition | 6 | 認識結果1件から同時に流す複製数（1〜6） |
| Surface Offset | 0.02 | スクリーン表面からの距離 |
| Japanese Font | BIZ-UDGOTHICR SDF | 既存の動的日本語フォント |

6個の文字オブジェクトを再利用し、位置・経過時間・通過時間を個別に管理する。
認識結果の通知側は `Enqueue(string)` のまま使用する。

## 検証

- Unity 6000.5.1f1 の生成済み応答ファイルを使用してEditor向け・Player向けのC#コンパイルを確認。
- 元のFBXで表示面がXY平面、法線が+Zであることを確認。
- Unityのバッチ起動はライセンス接続・システム初期化のエラーで終了したため、描画と実機動作は未確認。

Unity/Questでの確認項目:

1. 通常コマンドと不一致の発話の両方で、確定した同じ認識文字が6つ同時に流れ始める。
2. 途中認識で先行して反応しても、確定時に文字が表示される。
3. 無音ではコメントが追加されない。表示中に次の発話が確定したら、全6つが新しい認識文字へ切り替わり右端から再開する。
4. 日本語の読みやすさ、右から左への向き、黒縁、スクリーン端でのクリッピングを確認。
5. 映像の再帰的な映り込みがなく、キャラクターがコメントより手前で正常に遮蔽される。
6. シーン往復でコメントが残らず、コマンドの成功条件も従来どおりである。
7. 何度か発話して、6つの開始位置が毎回上下の各帯に分散し、帯の中で高さが変化することを確認する。速度の違いと文字サイズ5倍での可読性も確認する。
